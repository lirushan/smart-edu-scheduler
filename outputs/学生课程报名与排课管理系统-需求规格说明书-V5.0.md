## 2. 项目背景与目标

### 2.1 项目背景

高校选课是每学期初的刚性需求，选课时间高度集中，大量学生在同一时间涌入系统抢占有限课程资源，导致系统响应速度急剧下降。传统选课系统普遍存在以下痛点：

- **信息不对称**：学生对课程内容、教师风格、先修要求缺乏了解，选课决策盲目
- **资源分配不均**：热门课程秒光，冷门课程无人问津，教学资源利用率低
- **缺乏个性化指导**：系统不关心学生的学业短板和发展方向，选课与个人培养目标脱节
- **排课冲突频发**：人工排课效率低，课程时间、场地、教师冲突难以全面检测
- **缺乏自我诊断工具**：学生不了解自己的知识薄弱点，选课缺乏针对性

### 2.2 系统目标

本系统致力于打造一个**高并发、智能化、个性化**的新一代选课排课与学业评估一体化平台：

- **高可用与高性能**：支撑5000并发用户，选课提交响应时间 ≤ 2秒
- **数据一致性**：确保课程名额"零超卖"，选课记录绝对准确
- **智能推荐**：基于学生学业短板、兴趣偏好和发展目标，提供个性化课程推荐
- **智能排课**：自动生成无冲突课表，支持多约束条件优化
- **个性化智能出卷**：基于学生知识点掌握情况，自动生成针对性自测卷
- **全流程闭环**：从学业评估 → 能力画像 → 课程推荐 → 选课抢课 → 排课调整 → 成绩管理全链路覆盖

### 2.3 产品边界

**本期范围（V1.0 MVP）**：核心选课排课 + 基础题库考试，详见 [15. 产品分期策略](#15-产品分期策略)。

**明确不在本期范围**：
- 在线直播授课
- 视频会议集成
- 财务收费系统（学费缴纳）
- 宿舍管理系统
- 图书馆管理系统

## 4. 功能模块详细需求

> **说明**：本章在 V4.0 原文基础上进行了结构性重组和细化，与后续章节的数据模型、接口规范、状态机相互对应。

### 4.1 学生管理

#### 4.1.1 学生列表

- **多维查询**：支持按学号、姓名、院系、年级、班级、入学年份等多维度组合筛选与模糊搜索
- **批量导入/导出**：支持 Excel/CSV 批量导入学生账号（含初始密码生成），导出学生名单及选课状态报表
- **状态管理**：标注"在校/休学/毕业/退学"状态，休学与退学学生自动限制选课权限
- **学生画像**：自动聚合学生的成绩数据、选课记录、兴趣标签、知识点掌握度，生成可视化学生能力画像

#### 4.1.2 招生管理

- **新生数据对接**：支持对接招生系统自动导入新生数据，或手动录入批量生成账号
- **培养方案分配**：批量分配新生所属专业培养方案，决定其必修课程范围和可选课程池
- **入学能力评估**：新生入学后通过摸底测试，系统自动生成初始学科能力画像

#### 4.1.3 学业跟踪

- **学分进度监控**：实时统计学生已获学分、必修学分完成度、选修学分完成度，可视化展示毕业进度
- **学业预警**：当学生学分进度落后、GPA低于阈值或挂科数量超标时，自动触发学业预警通知
- **薄弱学科识别**：基于历史成绩数据和自测数据，自动识别学生的学科短板和知识薄弱点
- **培养方案完成度**：按学期展示培养方案中各模块的完成情况

---

### 4.2 课程管理

#### 4.2.1 课程列表

- **基础信息**：课程编码、名称、学分、学时、课程类别（必修/专业选修/通识选修/体育）
- **教学大纲**：支持上传 PDF/Word/视频等多媒体教学资料，供学生预览
- **教师信息**：关联授课教师、教师简介、教学评价星级
- **先修课程**：设置课程依赖关系，选课时自动校验先修课程完成情况
- **课程标签**：支持自定义标签（如"创新创业""双语教学""校企合作"），便于分类筛选

#### 4.2.2 课程库管理

- **课程申报**：教师在线提交新课程申报，填写课程大纲、教学目标、考核方式等信息
- **审核机制**：二级审核流程（院系初审 → 教务处终审），审核通过后进入课程库
- **版本控制**：记录课程每次修改历史，支持版本回溯
- **课程归档**：历史课程数据归档，不影响当前学期选课

#### 4.2.3 排课管理

- **智能排课引擎**：
  - **硬约束**：同一教师同一时间不冲突、同一教室同一时间不冲突、课程周学时满足要求
  - **软约束**：教师时间偏好、教室设备匹配、课程时间分布均衡
  - **算法支持**：基于遗传算法或多目标优化算法自动生成最优课表
- **可视化排课**：教务人员在日历界面上拖拽调整课程，系统实时提示冲突风险
- **排课结果发布**：排课完成后一键发布，学生端同步更新可选课程
- **调课管理**：支持学期中临时调课申请与审批，自动通知相关学生

#### 4.2.4 教学计划管理

- **培养方案管理**：按专业、年级维护培养方案，包含必修课程列表、选修学分要求
- **学期开课计划**：教务人员制定每学期的开课计划，从课程库中选择本学期开设的课程
- **开课申请审批**：教师提交开课申请，教务人员审批后纳入学期开课计划

#### 4.2.5 基础科目与专业科目分类体系

- **二级分类架构**：
  - **基础科目**：语言与文学、数学与逻辑、人文与社会、科学与技术、体育与健康、艺术与审美
  - **专业科目**：按学科门类划分（哲学、经济学、法学、教育学、文学、历史学、理学、工学、农学、医学、管理学、艺术学），每个门类下细分专业基础课、专业核心课、专业拓展课
- **统一数据标准**：课程表、题库、考试、成绩分析等所有模块统一使用该分类体系
- **分类筛选**：在课程列表、考试列表等界面提供按"基础/专业"科目分类筛选功能

### 4.3 教务教学管理

#### 4.3.1 报名管理（选课管理）

- **多轮次选课**：支持配置多个选课阶段：
  - **一轮初选（抽签制）**：学生自由选课，可选人数可超过容量，结束后系统随机抽签
  - **二轮补退选（抢课制）**：先到先得，实时扣减名额
  - **三轮退改选**：仅允许退课和少量调整
- **选课规则配置**：每轮独立配置适用年级、适用院系、选课门数上限、学分上限
- **特殊选课审批**：跨专业选课、学分超限申请、免修申请等走审批流程
- **管理员代选课**：教务人员后台为学生代选/退课，用于处理特殊情况

#### 4.3.2 抢课配置

- **限流策略**：配置 IP 限流（每分钟请求次数上限）、用户级请求频次控制
- **模式切换**：管理员一键切换"抢课模式"与"抽签模式"
- **黑名单管理**：恶意刷课 IP/用户加入黑名单，限制选课权限
- **选课白名单**：特定课程可配置仅开放给指定班级或年级

#### 4.3.3 选课记录

- **完整轨迹**：记录每次选课/退课操作的精确时间戳、IP 地址、操作来源（Web/小程序/后台）
- **冲突检测**：选课时实时校验"上课时间重叠"及"考试时间冲突"
- **选课日志**：学生可查看本人的选课/退课历史日志
- **管理员审计**：管理员可查询全校选课日志，支持按学号、时间、操作类型筛选

#### 4.3.4 课表查询

- **多维度课表**：支持按学生、教师、教室、班级维度查询课表
- **可视化展示**：周视图/列表视图切换，不同课程用不同颜色区分
- **缓存优化**：热门课表数据缓存至 Redis，降低数据库压力
- **课表导出**：支持导出为图片或 iCal 格式，便于导入手机日历
- **冲突高亮**：课表中自动高亮显示时间冲突的课程

#### 4.3.5 考务成绩管理

- **成绩录入**：教师端按平时成绩/期末成绩比例自动计算总评，支持 Excel 批量导入
- **成绩审核**：成绩提交后需经系主任/教务审核方可发布
- **成绩查询**：学生端查询各科成绩及绩点（GPA），支持历年成绩汇总
- **成绩分析**：自动生成成绩分布统计图、班级排名、专业排名
- **电子成绩单**：生成加密防伪的电子成绩单，支持下载和验证
- **补考/重修管理**：挂科学生自动纳入补考名单，补考成绩单独标记

#### 4.3.6 教学评价

- **评教配置**：教务人员配置每门课的评教问卷（可自定义题型和指标）
- **学生评教**：选课结束后学生对课程和教师进行匿名评价
- **评教统计**：自动汇总评教数据，生成教师教学评价报告
- **评教与成绩挂钩**：可配置"未完成评教则无法查看成绩"的规则

### 4.4 学业评估与考试模块

#### 4.4.1 题库管理

- **多题型支持**：单选题、多选题、判断题、填空题、简答题、计算题、编程题、论述题等
- **知识点标签化**：为每道题打上"科目-章节-知识点"的多级标签
- **难度分级**：标记题目难度（简单/中等/困难/极难），支持难度系数数值化（0-1 之间）
- **题目属性**：支持设置题目分值、预估作答时间、所属年级、适用考试类型
- **批量导入/导出**：支持 Excel/Word/文本批量导入题目，支持导出为 docx 格式
- **题目审核**：教师上传题目后需经题库管理员审核方可入库
- **题目版本管理**：记录题目每次修改历史，支持版本回溯

#### 4.4.2 知识点体系管理

- **知识图谱构建**：基于基础科目与专业科目分类，构建各学科的知识点图谱
- **知识点层级**：支持三级知识点结构（学科 → 章节 → 知识点）
- **知识点权重**：根据教学大纲为每个知识点设置考核权重
- **知识点关系**：维护知识点间的"前置-后继""关联-互补"关系

#### 4.4.3 考试管理

- **考试类型**：入学摸底考、单元/章节测试、期中、期末、模拟考、自主自测
- **考试配置**：考试名称、时间、时长、参与年级/班级、及格分数、考试模式
- **考试发布**：支持"立即发布""定时发布""密码准入"
- **考试监控**：实时监控考生在线状态、答题进度、异常行为（切屏、超时等）

#### 4.4.4 在线考试与作答

- **多端支持**：PC 浏览器和移动端（微信小程序）
- **自动保存**：答案定时自动保存至服务端，防止数据丢失
- **题目导航**：快速跳转到任意题目，实时显示答题进度
- **交卷模式**：支持"手动交卷"和"系统自动交卷"
- **防作弊机制**：题目/选项随机排序、切屏检测与提醒、随机抽题、IP 异常监控

#### 4.4.5 智能批改与成绩分析

- **自动批改**：客观题自动评分
- **主观题 AI 辅助批改**：利用 AI 大模型对简答题、论述题等进行智能评分
- **人工批改**：教师在线批改主观题，支持批注和评分
- **成绩报告**：个人报告（总分、得分率、雷达图、薄弱点 TOP5）和班级/年级报告

#### 4.4.6 错题本与薄弱点追踪

- **自动收录**：考试/自测中的错题自动收录到学生个人错题本
- **错题分类**：按科目、知识点、错题原因分类
- **薄弱点追踪**：动态追踪各知识点的掌握度变化趋势
- **掌握度可视化**：以热力图或进度条形式展示掌握程度（0%-100%）

### 4.5 个性化智能出卷模块

#### 4.5.1 学生能力画像（出卷数据基础）

- **多源数据融合**：整合历史考试成绩、自测数据、课堂表现、作业完成情况
- **知识点掌握度矩阵**：为每个学生在每个知识点上建立掌握度评分
- **能力维度**：各知识点掌握度、各题型熟练度、难度适应度、学习曲线
- **动态更新**：每次考试/自测后实时更新能力画像

#### 4.5.2 智能组卷引擎

**组卷算法**：

1. **基于遗传算法的智能组卷**：将组卷方案编码为染色体，多目标优化迭代
2. **基于深度知识追踪的个性化组卷**：DKVMN 等模型精准预测掌握概率
3. **基于决策树的自适应选题**：根据上一题表现动态决定下一题
4. **基于知识图谱的试题推荐**：结合知识图谱与知识追踪实现个性化推荐

**组卷模式**：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **短板聚焦模式** | 重点覆盖学生掌握度最低的 TOP-N 知识点 | 针对性补弱 |
| **均衡覆盖模式** | 按教学大纲权重均匀覆盖各知识点 | 全面复习 |
| **难度自适应模式** | 从学生当前水平出发，逐步提升难度 | 能力提升训练 |
| **错题重练模式** | 以学生错题本中的错题相似题为主 | 错题巩固 |
| **综合诊断模式** | 混合以上策略，全面评估学生水平 | 阶段性测评 |
| **AI 智能模式** | AI 根据学生画像自动选择最优组卷策略 | 日常自测 |

#### 4.5.3 学生自测流程

1. 学生选择自测模式
2. 可选参数配置（范围、题量、题型偏好、难度偏好）
3. 系统生成个性化试卷
4. 学生在线作答
5. 实时批改与反馈
6. 结果报告与学习路径推荐

#### 4.5.4 AI 智能出卷（基于大模型）

- **自然语言出卷**：学生可用自然语言描述出卷需求
- **材料智能出卷**：上传学习材料，AI 自动提取知识点并生成试题
- **智能提示词优化**：内置优化的 Prompt 模板
- **流式生成**：实时显示 AI 生成试卷的过程

#### 4.5.5 自测历史与成长追踪

- **自测记录**：完整记录每次自测的试卷、答案、得分、用时
- **成长曲线**：展示各知识点掌握度随时间的动态变化趋势
- **能力雷达图**：动态更新个人能力雷达图

## 6. 核心业务流程

### 6.1 选课全流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  教务配置    │───▶│  一轮初选    │───▶│  二轮补退选  │───▶│  三轮退改选  │
│  选课轮次    │    │  (抽签制)    │    │  (抢课制)    │    │  (调整期)    │
└─────────────┘    └──────┬──────┘    └──────┬──────┘    └──────┬──────┘
                          │                  │                  │
                          ▼                  ▼                  ▼
                    学生自由选课         先到先得抢课         仅允许退课
                    志愿可超容量         实时扣减名额         少量补选
                          │                  │                  │
                          ▼                  ▼                  ▼
                    系统随机抽签         Redis DECR         最终名单锁定
                    公布结果             原子扣减            生成正式课表
```

**流程详细步骤**：

**阶段 0 — 教务配置**：
1. 教务创建学期，配置选课轮次（轮次类型、时间窗口、限选规则）
2. 教师提交开课申请 → 教务审批 → 开课实例入库
3. 智能排课引擎生成课表 → 教务调整确认 → 发布排课结果
4. 教务启动选课轮次

**阶段 1 — 一轮初选（抽签制）**：
1. 学生浏览可选课程，将心仪课程加入"选课志愿"
2. 选课志愿可超过课程容量（如容量 50，可选 200 人）
3. 时间窗口关闭后，系统对每门课程进行随机抽签
4. 抽签逻辑：
   - 每门课程独立抽签
   - 优先满足必修课程需求（如某课程对本专业为必修，则本专业学生优先）
   - 随机算法需保证公平性（使用密码学安全随机数）
5. 公布抽签结果，学生收到选课成功/失败通知
6. 未选中课程释放名额至下一轮

**阶段 2 — 二轮补退选（抢课制）**：
1. 学生查看剩余有名额的课程
2. 点击选课 → 前端发起请求 → 后端 Redis DECR 原子扣减
3. 扣减成功 → 异步写入 MySQL → 返回成功
4. 扣减失败（名额=0）→ 返回"已满"
5. 学生可退选已中签但不想要的课程（名额+1）
6. 实时展示剩余名额

**阶段 3 — 三轮退改选**：
1. 仅允许退课操作
2. 特殊情况（如课程取消）可由管理员代选

### 6.2 智能排课流程

```
教师时间偏好 ──┐
教室资源     ──┼──▶ 约束建模 ──▶ 遗传算法求解 ──▶ 生成候选课表
课程周学时   ──┘                              │
                                               ▼
                                    教务可视调整（拖拽）
                                               │
                                    冲突检测（实时提示）
                                               │
                                               ▼
                                    排课结果发布 ──▶ 学生端同步
```

**约束优先级**：

| 优先级 | 约束类型 | 约束内容 |
|:------:|---------|---------|
| P0 | 硬约束 | 同一教师不能同时出现在两个课堂 |
| P0 | 硬约束 | 同一教室不能同时安排两门课 |
| P0 | 硬约束 | 课程周学时 = 排课次数 |
| P1 | 软约束 | 教师时间偏好（如不想早起） |
| P1 | 软约束 | 教室设备与课程需求匹配 |
| P2 | 软约束 | 课程在一周内分布均匀 |
| P2 | 软约束 | 同一班级课程尽量不连排 |

**冲突检测规则**：
- `(schedule_slot.day_of_week, schedule_slot.start_period, schedule_slot.end_period)` 作为冲突检测维度
- 两段时间重叠判定：`max(start1, start2) < min(end1, end2)`
- 冲突检测需同时交叉检查 `teacher_id`, `classroom_id`, `class_id`

## 9. 数据库设计概要

### 9.1 命名规范

### 9.2 核心索引设计

## 10. 异常场景与容错设计

### 10.1 选课异常场景

| 场景 | 触发条件 | 处理策略 |
|------|---------|---------|
| **超卖** | Redis 扣减成功但 MySQL 写入失败 | 补偿机制：定时任务比对 Redis 和 MySQL，回补名额 |
| **重复提交** | 用户快速双击选课按钮 | 接口幂等：Redis 分布式锁（Key：`course_id:student_id`） |
| **Redis 宕机** | 选课高峰期 Redis 不可用 | 降级方案：切换到 MySQL 行锁 SELECT FOR UPDATE（性能下降但可用） |
| **抽签公平性** | 质疑抽签算法不公 | 使用 `SecureRandom` + 抽签过程日志可审计 |
| **选课时间窗口** | 用户本地时间与服务器时间不一致 | 所有时间判断以服务器时间为准，前端提示服务器时间 |

### 10.2 考试异常场景

| 场景 | 触发条件 | 处理策略 |
|------|---------|---------|
| **网络中断** | 考试中网络断开 | 答案定时自动保存（每 30 秒），恢复后继续 |
| **浏览器关闭** | 考试中关闭浏览器 | 服务端保持会话，重新打开可继续（倒计时不暂停） |
| **切屏作弊** | 学生切出考试页面 | 第 1 次警告，第 2 次标记，第 3 次自动交卷 |
| **服务器过载** | 大量学生同时开考 | 答案保存异步化，使用消息队列缓冲 |

### 10.3 排课异常场景

| 场景 | 触发条件 | 处理策略 |
|------|---------|---------|
| **无可行解** | 约束过度导致无排课方案 | 提示教务放宽软约束（如扩大教室范围） |
| **临时调课** | 学期中临时需要调课 | 调课后自动检测新时间是否冲突，通知受影响学生 |

### 10.4 系统级容错

| 场景 | 触发条件 | 处理策略 |
|------|---------|---------|
| **缓存雪崩** | 大量缓存同时过期 | 缓存过期时间加随机值（基础 TTL + random(0, 300s)） |
| **缓存穿透** | 查询不存在的数据穿透到 DB | 布隆过滤器 + 空值缓存（TTL 60s） |
| **数据库主从延迟** | 写入后立即查询读不到 | 关键操作强制读主库，非关键操作接受短暂延迟 |
| **消息队列积压** | 消费者处理速度跟不上 | 监控队列深度，触发告警；增加消费者实例 |

## 13. 高并发技术实现方案

> **说明**：本章在 V4.0 原文基础上补充了更具体的实现细节。

### 13.1 核心挑战与解决方案

| 核心问题 | 技术方案 | 实现细节 |
|---------|---------|---------|
| **超卖问题** | Redis DECR + 异步落库 | 选课时 DECR `course:capacity:{offeringId}`，结果 ≥0 则成功；异步写 MySQL |
| **接口幂等** | Redis 分布式锁 | Key: `lock:enroll:{studentId}:{offeringId}`，TTL 5s，SET NX EX |
| **系统限流** | 网关令牌桶 | Gateway 配置 per-IP 和 per-User 双维度限流 |
| **缓存策略** | 多级缓存 | Caffeine 本地缓存（1min）+ Redis（5min），预热热门课程 |
| **数据库优化** | 读写分离 + 分库 | ShardingJDBC 按 student_id 分 4 库 |
| **异步处理** | RabbitMQ | 选课日志、通知推送异步消费 |
| **智能组卷** | 并行计算 | 组卷子任务并行执行（按知识点分组并发查题） |

### 13.2 Redis 选课扣减关键逻辑

```
1. 检查分布式锁 → 已存在则返回"请勿重复操作"
2. 检查选课时间窗口 → 未开放则拒绝
3. 检查先修课程 → 未完成则拒绝
4. 检查时间冲突 → 有冲突则拒绝
5. DECR course:capacity:{offeringId}
6. 如果结果 >= 0 → 选课成功
7.    → 发 MQ 消息：enrollment.success.{offeringId}
8.    → 消费者：INSERT INTO reg_enrollment
9. 如果结果 < 0 → 选课失败，INCR 回补
10. 释放分布式锁
```

## 19. 安全设计细化

### 19.1 认证安全

- 密码使用 BCrypt 加密存储，不可逆
- Token 使用 JWT，有效期 Access Token 2h + Refresh Token 7d
- 连续登录失败 5 次，账号锁定 30 分钟
- 支持强制修改初始密码

### 19.2 接口安全

- 所有 API 需要有效 Token 方可访问（白名单除外：登录、健康检查）
- 敏感操作（选课、退课、成绩录入）需二次验证 Token 中的用户身份
- CUD 操作必须携带 CSRF Token（Web 端）
- SQL 注入防护：使用 MyBatis 参数绑定，禁止拼接 SQL
- XSS 防护：前端输出转义 + Content-Security-Policy 头

### 19.3 数据安全

- 密码字段：BCrypt 加密，不可逆
- 成绩字段：AES 加密存储于数据库
- 传输安全：全站 HTTPS，HSTS 头
- 日志脱敏：审计日志中手机号、身份证号中间位脱敏

### 19.4 防作弊

详见 [4.4.4 在线考试与作答](#444-在线考试与作答)。
