# 智教通业务闭环待办清单

更新时间：2026-07-08

## 当前判断

系统已经能支撑基础演示，但仍有几条业务链路没有完全闭环。今天已先处理顶部铃铛不可点击的问题：前端已增加通知面板、未读数、全部已读、按角色跳转相关页面。完整站内信还需要后端表、接口和业务事件接入。

## 待闭环模块

| 优先级 | 模块 | 当前状态 | 需要补齐 |
|---|---|---|---|
| P0 | 消息通知 | 前端铃铛可点；后端只有 RabbitMQ 消费日志 | 增加 `sys_notification` 表、通知查询/已读接口、业务事件落库 |
| P0 | 课程 | 课程审核可用；教师缺提交/维护开课申请入口 | 教师端开课申请页面、草稿/提交/撤回、审核后进入课程广场 |
| P1 | 排课 | 教务能看课表；缺编辑能力 | 排课新增/编辑、教室/教师/学生时间冲突检查、调课通知 |
| P1 | 考试 | 建考试、学生考试、成绩查看可跑；缺组卷入口 | 绑定试卷/题目、设置分值、考试状态自动流转 |
| P1 | 抢课 | Redis 锁和 MQ 同步存在；缺可验收证据 | 并发压测脚本、抢课日志页面、名额初始化/重置运维入口 |
| P2 | 权限 | 菜单授权和接口隔离可用 | 权限变更审计日志、授权变更记录查询 |
| P2 | 报名 | 选课/退课可用；错误提示偏粗 | 选课失败原因结构化展示，如容量不足、时间冲突、重复报名 |

## 消息通知后端建议

1. 建表：按需求文档补 `sys_notification`，字段至少包括接收人、标题、内容、类型、已读状态、跳转路径、创建时间、读取时间。
2. 接口：`GET /notifications/my`、`GET /notifications/unread-count`、`PUT /notifications/{id}/read`、`PUT /notifications/read-all`。
3. 事件接入：选课成功/失败、课程审核结果、成绩发布、考试提醒、调课结果写入通知。
4. 前端替换：把当前本地通知面板改为真实接口数据，保留现有样式和交互。

## 下一步建议

先做 P0 的消息通知后端和教师开课申请。原因是这两块会把“课程 > 审核 > 学生选课 > 通知反馈”的主线补完整，验收价值最高。
